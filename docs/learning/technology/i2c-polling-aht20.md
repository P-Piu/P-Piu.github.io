# I2C 轮询：读取 AHT20 温湿度

这次练习在 STM32F103C8T6 上使用 I2C1 的轮询模式读取 AHT20 温湿度，并通过 USART2 输出结果。轮询会阻塞程序，但它的执行顺序最直观，很适合作为第一次跑通 I2C 设备的方式。

## 完整读取流程

```text
初始化
→ 发送 0xAC 0x33 0x00 测量命令
→ 等待至少约 75 ms
→ 接收 6 字节
→ 检查忙位
→ 拼接两个 20 位原始值
→ 换算温湿度
```

上电后先等待约 40 ms，再读取状态；必要时发送 `0xBE 0x08 0x00` 完成初始化。状态字节的 bit7 为 1 表示传感器仍在忙，只有它变为 0 后才能解析数据。

## 原始数据怎样拼起来

AHT20 返回的温度和湿度各占 20 位，其中 `readBuffer[3]` 同时包含两者的一部分：高 4 位属于湿度，低 4 位属于温度。

```c
uint32_t humidityRaw =
    ((uint32_t)readBuffer[1] << 12) |
    ((uint32_t)readBuffer[2] << 4)  |
    ((uint32_t)readBuffer[3] >> 4);

uint32_t temperatureRaw =
    (((uint32_t)readBuffer[3] & 0x0F) << 16) |
    ((uint32_t)readBuffer[4] << 8) |
    readBuffer[5];
```

换算关系为：

```text
湿度 = rawH × 100 / 2^20
温度 = rawT × 200 / 2^20 - 50
```

## 排错记录

- 首次数据异常：先初始化温湿度变量，并检查 HAL 函数的返回值
- 状态一直显示忙：增加等待时间，再检查命令与总线连接
- 温湿度数值互换：确认函数参数的顺序
- 传感器断线后程序卡死：避免长期使用 `HAL_MAX_DELAY`，改用有限超时

这一步已经实际跑通。它也为后面改成中断和 DMA 模式提供了一条可以对照的基线：先确认数据本身能够正确读取，再改变程序怎样等待和搬运数据。
